# 帧率、清晰度与采样

看课时视频是否流畅、保存的公式和文字是否清晰，会直接影响学习和复习。本页说明 Vidence 本地播放与截图保存的方式，并列出已经测过的分辨率和帧率。

本地播放器使用 Qt QVideoWidget 原生视频输出。显示链路没有固定24帧限流，也不逐帧转QImage、缩放和压JPEG。取图时才从最新视频帧生成一份采样图，显示与OCR采样分开。

## 2026-11-11 实测

同一30帧H264原视频的对照：旧链路每秒交付约15.09帧，新链路30.00帧；帧回调平均5.55ms降至0.34ms。暂停、拖动进度、音量/静音、全屏、Esc恢复侧栏、控件自动隐藏和底部退出通过。

| 测试源 | 精确帧率 | Qt窗口帧交付 |
| --- | --- | --- |
| 1280×720 | 60/1 | 59.93 fps |
| 1920×1080 | 60000/1001 | 59.85 fps |
| 1920×1080 | 30000/1001 | 30.00 fps |
| 3840×2160 | 24000/1001 | 23.98 fps |
| 3840×2160 | 60/1 | 59.97 fps |

使用FFmpeg生成每帧独立变化的12秒H264测试图，用ffprobe核对真实分辨率和有理数帧率。每个源在独立的静音Qt窗口测量，自动关闭；此组帧返回RhiTextureHandle，测试代码保存在scripts/playback-matrix.py。没有把30帧重复成60帧来充当真实60帧素材。

这里测的是帧进入Qt原生输出的节奏，不是显示器最终呈现率。HDR、10bit、HEVC/AV1、可变帧率长片、不同显卡和屏幕仍需要独立验收。不能将本机H264结果泛化到所有编码器和硬件。

采样保留微秒时间戳换算的媒体时间，不将23.976/29.97/59.94取整。播放、1280宽的低成本预览/OCR和最高3840宽的存档原图分开；只有选中候选图时才生成高质量JPEG，不把低清预览当成存档。已有默认1280配置会迁移，用户明确设置的尺寸继续保留。

4K细字/细线H264测试片中，真实存档保持3840宽；薄线对比度约110，旧1280预览放大后约28。脚本为scripts/frame-detail-check.py，测试图是生成素材，不代表真实平台4K账号播放已验收。

实现依据：[Qt QVideoWidget](https://doc.qt.io/qtforpython-6/PySide6/QtMultimediaWidgets/QVideoWidget.html)、[Qt QVideoFrame](https://doc.qt.io/qtforpython-6/PySide6/QtMultimedia/QVideoFrame.html)。
