# 干净云环境验收

源码从空工作目录检出，使用npm ci安装锁定依赖，不上传本机node_modules、Python环境、模型、浏览器会话、课程或密钥。

仓库的BETA工作流分为四个任务：

1. Linux源码：TypeScript、全部Vitest、生产构建、生成视频的扩展闭环、侧栏布局与桥接。
2. Windows源码与打包：重新安装开发依赖，Python检查、设置界面、原生帧率矩阵、4K存档细节、无OCR记录，随后生成独立发行包。
3. 另一台干净Windows runner：下载发行包和明确标注的生成测试片，不安装项目的开发依赖；限制目标进程PATH，核对随包Qt/Python绑定和Node桥接，并让冻结程序实际解码720p H264，验证进度、尺寸和两次不同像素。不把解码结果当成显示器呈现率。
4. 发布：仅在源码与独立运行验收通过后，将同一份已测文件打成ZIP，生成SHA-256并发布BETA版本；不覆盖已有版本。

GitHub托管runner和Codex云环境通常预装工具，因此第三项不等于物理卸载Python/Node，更不等于完全空白Windows。报告记录初始工具与验证边界。缺少WebView2的真实安装、最终显示器帧率和用户账号课程仍需相应环境验证。失败的任务必须保留日志；不能通过降低断言把失败写成成功。

云端只生成无账号测试片，不执行需要OpenCode Go/DSH额度的真实模型脚本。原媒体图片问答的本机结果见verification.md；两种证据分别保留。

若云端默认检出的提交较旧，应先fetch并检出本次明确指定的提交，再核对git rev-parse HEAD。测试状态以实际任务日志为准，配置了工作流不表示已通过。
