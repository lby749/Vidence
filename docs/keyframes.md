# 知识画面与真实图片问答

画面变化只产生候选图。用户允许后，视觉助手真正读取原图，再区分知识、纯讲者、片头片尾和无法判断的内容。判断依据是画面有没有可复习的图示、公式、文字或操作；讲师与板书同框、没有文字的科学图解和临近片尾的总结页均可保留。

## 使用

设置 → 学习偏好 → 允许发送视频截图。选择自动筛选，或到视频库 → 原文与节点 → 知识画面点击筛选。原图不会因分类而删除；不确定与已过滤画面可展开查看，点击“保留这张画面”恢复。筛选失败可重试，只处理未完成的图。

聊天里勾选“允许读取画面”。问答先用本视频摘要和检索线索，再按需 get_frame 读取原图。OpenCode Go 的 MCP 工具会传真实图片内容，回答引用保留原图 ID 与媒体时间；点引用能打开原图。默认每个问题最多两张，筛选批次最多六张，遵守小时与每日预算。

## 问答对照

没有向模型提供字幕、OCR答案或答案提示：

- 数学原图：读出 a²+b²=N、65=5×13，返回实际图片引用。
- 同一问题禁用图片：明确表示没读图，不虚构公式。
- 固定问题、标题与播放位置，仅换成Excel图：读出红楼梦/《红楼梦》、西游记/《西游记》，不沿用数学内容。

换图是控制实验，固定时间用来排除元数据提示，不把该时间说成Excel的实际播放位置。模型仍有小字误读风险，输出逐字正确率未做全面标注。

## 修复的实际问题

- OpenCode Go路线不再将 allowImages 固定关闭，MCP结果保留图片 MIME 和数据；浏览器侧栏与独立应用聊天均有图片选项。
- 图片预算按真实读图数计数，修复问答循环重复累计。
- 图像引用只来自本请求真正读取过的原图；其他视频、选中范围之外、请求之后加入的图不能越权读取。
- 模型生成的图片摘要只作查找线索，仍须读取原图才能作为画面引用。
- 模型分类JSON语法错误最多做一次文字修复，不重复上传图片；校验ID、数量、类型、取消及视频是否仍存在，整批提交。
- 待确认画面独立呈现；低分的“知识”分类不单凭分数删除，避免误伤无字图解。
- 高清存档单独取原图，最高3840宽；预览/OCR仍轻量采样。连续运动等待八秒后允许同场景变化，避免预览与高清取帧的微小时间差让动画一直无法保存；真正转场仍拒绝。
