# 后台消耗检查与优化

日期：2026-11-10。下方 CPU 与历史 token 表为上一轮检查时的阶段快照，四档与语言/风格新增验证见文末。只统计本项目助手进程、独立应用数据和本项目桥接工作目录中的 DSH 调用，未把其他浏览器、Codex 聊天或用户其他项目的消耗加进来。

## 实测数据

### CPU 与内存

本机 20 个逻辑处理器，每段采样 8 秒。CPU 用进程 CPU 时间增量计算，再除以逻辑处理器数得到整机百分比；内存为相关进程工作集相加，包含共享页，单位 MiB。

| 场景 | 整机 CPU | 工作集合计 | 原始数据 |
|---|---:|---:|---|
| 停止闲置采集前 | 0.750% | 1266.8 MiB | artifacts/resource-before.json |
| 显式停止采集与本地播放后 | 0.029% | 1270.7 MiB | artifacts/resource-stopped.json |
| 新成品完成识别、检索和问答后闲置 | 0.049% | 1221.2 MiB | artifacts/resource-packaged-stopped.json |
| 最新成品普通启动，未打开视频、未加载离线计算 | 0.078% | 416.7 MiB | artifacts/resource-normal-idle.json |

第一组前后对比中，CPU 下降约 96%。停止采集不会立即卸载已经加载的离线模型，因此内存没有同步减少。这是短时采样，不能当作长课程的平均或峰值。

离线模型缓存约 326.2 MiB；独立应用的 IndexedDB 在本次检查时不足 1 MiB。记录的文字和对话不是当前主要的磁盘负担。本次未保存视频副本或关键帧图片，后续大量保存截图时需重新测量。

应用目录约 791 MB（十进制），包括 Qt、Node 和推理运行时；发布包内模型权重为 0。用户下载的离线功能另占模型缓存空间。

当前新成品位于 dist/desktop-preferences/视频记忆助手。旧 dist/desktop、dist/desktop-update 包仍保留在开发目录；它们不是普通用户安装时需要的额外程序。源码测试状态 .desktop-state 约 734 MB，保留的测试模型约 342 MB，均为开发测试数据，不随发布。替换旧包的删除命令曾被自动审批拒绝，因此改在新目录构建，没有删除旧数据。

## 已做的优化

1. 结束记录自动停止原生采集与本地播放；闲置切到视频库时停止采集和轮询。外部课程播放器由原平台控制，界面明确提示在原窗口暂停。
2. 不再为每个预览帧生成 Base64；仅在前端实际取帧时编码。实时预览继续使用本地 JPEG 流。
3. 计算沙箱延后到首次 OCR、嵌入或重排调用才创建；普通打开应用、看设置时不提前加载。
4. 有本视频长期记忆且未选定片段时，先直接读取记忆，跳过会被丢弃的初始向量检索与神经重排；模型按需核对原文的工具保留。
5. 关闭本项目一次性 DSH 任务的 AI 标题生成，保留本地标题回退；用户的全局 DSH 设置没有修改。关闭后新测试未新增标题模型请求。
6. 使用 DSH 官方 --json 协议累计 step_end 用量，包含缓存输入和多轮回答；缺失用量明确标为“未返回”，不再显示成免费。摘要、回答、失败和取消记录字符数、耗时及状态，不保存完整提示词或连接码。
7. 已有每日 token 预算也应用于本地智能体，达到已知预算后不再发起下一次摘要或问答。
8. 窗口列表刷新期间禁用旧选择，防止异步结果清空刚选中的窗口；记录中拒绝引用跳转切换播放器，停止记录后正确恢复本地来源与界面。

DSH 的 [官方命令行协议](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cli-help.md)、[JSON 用量实现](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/bundle/headless/src/json-stream.ts)和[独立标题生成说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/session/session-title-first-prompt-llm/README.md)用于核对接口；实际通过情况以本机报告为准。

## 验证与限制

编译、92 项单元测试、2 项 Python 测试、设置与模型离线测试、桥接鉴权和真实 token 返回均通过。成品本地视频自动暂停、延迟加载、异步窗口刷新，以及自建动态窗口的停止/恢复采集有独立验收脚本。真实高途记忆问答及版本、来源和用量通过，见 artifacts/desktop-chat-e2e.json。

最新新目录成品的 window-idle-e2e.json 还确认：记录中切换来源被拒绝；停止后能从窗口采集恢复本地视频，并更新视频库定位。成品 31 个前端资源及桥接脚本与当前构建逐文件相符，内置 Node/桥接检查通过。测试助手与自建窗口已退出，当前打开的是无视频参数、无调试端口的普通实例，见 artifacts/desktop-normal-start.json。

浏览器电脑操作仍被工具的自动网址校验拦截；本轮未再次访问第三方浏览器窗口，也未把其测试视频标记为已关闭。常见平台入口不等于全部账号和整节课程均已验收。

长课程峰值内存、连续数小时 OCR、其他语言 OCR 和全部平台账号流程仍需单独测试。当前主要负担是首次加载的离线模型，以及长视频整理和多轮模型问答；文字数据库本身很小。

## 四档与量化资源更新

用户现在可以选择无占用/低占用/中占用/高占用，资源总量 0/21.5/46.1/342.0 MB，按档位增量下载并控制实际运行开关。降档卸载已有计算、保留下载缓存；无占用只表示不加载本地 AI 模型，应用及已接服务仍有基础占用。完整降档和无模型云端问答分别经 desktop-preferences-e2e.json、desktop-style-e2e.json 验证。

语义模型 Q8、精排 INT8 已核对真实 ONNX 权重及量化算子。OCR 是轻量非量化版。小样本检索 7/8、精排 5/6、5 张 OCR 图归一化字符准确率 100%，不宣称公开基准或 FP32 精度对照。更多说明见 setup-models.md 和 artifacts/quantized-quality.json。


## 原生 Q4 检索与本轮界面

独立应用采用 EmbeddingGemma 300M Q4_K_M + llama.cpp b11597，权重236337120 bytes。固定公开 XQuAD 子集每语种50问、240候选段：原BGE small Q8 中/英/德 41/19/2，新原生Q4 45/48/44；并非完整MTEB，也不是课程问答准确率。相同空白页面加推理进程的私有峰值约463→337MiB、工作集约721→670MiB，不能冒充整个成品APP的等条件RAM结论。GPU优先/自动CPU回退实测见 native-embedding-check.json（真实Vulkan后注入一次错误，真实CPU重启，余弦.9998009897）；AMD和Metal硬件仍未实机测试。

界面翻译使用本地字典，不调用模型。窗口跟随仅在几何/可见性变化时更新；相同网页窗口已经采集时不重复stop/start，避免无效刷新。自动验收已改为无账号headless浏览器和Qt offscreen，避免在用户当前窗口反复切换全屏。新的隔离桌面验收启动命令曾被自动审批以blocked by policy拒绝，未换方式重试该动作。
